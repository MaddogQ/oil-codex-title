# oil-codex-title

让 Codex 侧边栏的话题名称跟上实际讨论内容。

用户明确收尾触发 Stop 检查，或会话结束触发 SessionEnd Hook 后，插件在后台读取最近 3～5 轮有效对话与原始目标，由独立模型判断持续主线和完成状态。标题使用 `YYMMDD [类别] 对象｜目标`，明确完成时在最前面增加 `✓ `。外层项目已提供名称时，标题默认省略重复项目名；monorepo 子项目、上级目录操作或跨项目歧义除外。

## 安装与开始使用

这是本地 Codex 插件，适用于支持生命周期 Hook 的桌面版本。需要 Python 3.10+ 和已登录的兼容 Codex CLI；无需另外保存 API Key。本 fork 沿用上游现有模型调用方式和配置。当前代码默认 `gpt-5.6-luna`、低 reasoning effort、`service_tier=priority`；已有账号配置仍保留。本次标题策略不新增固定模型或路由，不修改 Fast/Standard 策略，也不切换主对话模型。命名消耗当前账号的模型额度。

直接把下面这段话发给 Codex，让它查找仓库并完成安装：

```text
帮我克隆 MaddogQ/oil-codex-title 的 codex/personal-title-policy 分支，按 docs/Windows安装与验证.md 配置本地插件市场并安装完整插件，包含 Stop 和 SessionEnd Hook，不要只安装 Skill。检查 PATH 中的 Python 3.10+、Codex CLI、hooks 开关和 doctor，告诉我界面安装、启用与信任 Hook 的步骤。保留 upstream，不开启归档，不批量修改历史标题。
```

Windows 完整流程见 [安装个人 fork](Windows安装与验证.md)。安装完成后：

1. 让 Agent 执行插件中的 `doctor`，确认可执行文件和话题读取能力。
2. 确认 Codex 的 `features.hooks` 已开启；可通过 `codex features enable hooks` 开启。
3. 在 Codex 的 Hook 管理入口检查并信任本插件的 **Stop 和 SessionEnd Hook**。CLI 使用 `/hooks`。安装插件本身不会自动信任 Hook；升级后也要检查新增定义。
4. 在新的正常对话中验收，等待后台模型返回后检查侧边栏标题与本地日志。

需要信任的行为：执行插件的 `scripts/oil_codex_title.py hook`，读取当前本地话题、调用独立临时命名模型，并通过官方 `thread/name/set` 更新标题。它不恢复原话题、不发送新消息、不直接改写话题数据库。

## 命名方式

标题固定为 `YYMMDD [类别] 对象｜目标`。完成后为 `✓ YYMMDD [类别] 对象｜目标`，例如：

```text
260904 [分析] Codex｜Luna 后台调用
✓ 260904 [分析] Codex｜Luna 后台调用
```

### 分类

类别按整个话题的主要工作模式选择，不因一个临时阶段切换。

| 类别 | 主要工作模式 |
| --- | --- |
| 实现 | 实现新功能、代码、自动化、插件、脚本或具体能力 |
| 设计 | 设计 UI、UX、系统架构、玩法、流程、交互或视觉方案 |
| 排障 | 定位或修复明确异常、错误及非预期行为 |
| 优化 | 改善已经可用方案的质量、性能、体验、Prompt 或工作流 |
| 配置 | 设置环境、参数、模型、工具链、安装、连接及运行方式 |
| 分析 | 理解、解释、比较或判断已经明确的信息和机制 |
| 调研 | 搜索外部资料、现状、案例、产品、社区或文档 |
| 规划 | 安排未来路线、项目步骤、旅行、布局或执行计划 |
| 创作 | 生产故事、设定、节目、Prompt、视觉概念、文本或音乐 |

分析是理解或判断已有对象；调研是到外部寻找资料和案例。类别名称固定使用上述中文，标题的对象和目标跟随近期用户实质需求的主要语言，保留产品名和技术名词。偶尔一句外语不切换语言。

### 日期与状态

模型只输出 `[类别] 对象｜目标` 的 canonical title 和 `active | completed` 状态。Python 从真实 thread metadata 的 `createdAt` 计算日期，再组合 display title。模型不得生成日期或 `✓`。

`createdAt` 按运行插件机器的当地时区计算，包括 DST 和跨日。例如 `2026-09-05T05:30:00Z` 在 America/Los_Angeles 是 9 月 4 日 22:30，标题日期为 `260904`。不使用 `updatedAt`、最后一轮时间、文件 mtime 或 state 文件创建时间。每 thread state 分别保存 `created_date` 与 `completion_status`，不从原标题或 `✓` 猜状态；真实 `createdAt` 是日期来源。缺少可靠 metadata 时保留原标题，报告 `metadata_unavailable`。若按本机时区重新计算的日期与已保存日期不一致，报告 `metadata_changed` 并保留原标题，不悄悄更换日期。

`active` 表示工作仍在继续，标题没有状态字符。`completed` 需要用户明确结束整个话题；仅有 assistant 宣称“完成”不足以结束。不确定时保持 `active`。供判断的用户消息被截断或轮次内容不完整时，程序也保守保持 active。

| 用户消息 | 状态 |
| --- | --- |
| 可以了，谢谢 | completed |
| 确认了，可以不用追踪了 | completed |
| 验收通过，收尾吧 | completed |
| 验收没问题，可以收尾 | completed |
| 这个功能验收通过，接下来处理登录页 | active |
| 可以，继续 | active |
| 好的，下一步看…… | active |

完成的 thread 收到新的实质任务后重新变为 `active`。例如 `✓ 260904 [设计] 存档管理｜删除交互` 去掉 `✓ ` 后，日期仍为 `260904`。canonical title 不变但状态改变时，也需要更新 display title。

### 稳定性与历史标题

对象在前，目标在后，恰好一个全角分隔符。默认参考最近 5 轮有文字的对话和原始目标，描述整个 thread 的持续主线。设计讨论进入实现阶段、临时测试、排错或“继续”不会自动成为新主线，只有长期目标明显转移才允许 rename。

已有稳定基线后的纯确认可以跳过模型，保留原有跳过上限与保护。包含完成、验收、收尾或新的实质需求的消息必须进入状态判断。`继续` 和 `可以，继续` 保持 active；completed 话题不能因标题稳定而漏掉重新激活。

不批量扫描历史 thread，不因安装、策略升级或旧 emoji 格式单独改名。Stop 与 SessionEnd 只检查事件所属的单个话题，且当前主线或 completion 判断确需更新时，才按新格式生成标题。旧 state 缺少新字段时仍可继续运行。

completion 不代表 archive。本 fork 不创建归档计划，不把 `completed` 接入归档；上游独立归档代码保留并默认关闭，历史技术说明见 [归档工作流](归档工作流.md)。命名规则集中在 `../prompts/naming.md`。

## 控制方式

Windows 命令使用 `python` 替代 `python3`。后台默认最多同时运行 2 个命名模型；`max_parallel_workers` 可设为 1～8，排队计入单次模型超时预算。结束进程会短暂检查最后轮次完成状态，未完成或已过期的事件保留原标题并记录原因。

CLI 正常 `/exit` 或 `/quit` 引发 SessionEnd 时，Hook 快速启动独立命名进程并返回；标题可能在 CLI 退出后才更新。宿主的结束 Hook 最多执行 3 秒，模型不能在这个窗口内同步运行。后台进程复用轮次检查、锁、指纹、暂停和手工标题保护；同一内容重复结束不再调用模型；普通 Stop 只读最新轮用户文本，只有明确整句收尾才调用模型。异常杀进程或系统关机不能保证触发或完成。

`/clear` 创建新会话，旧会话脱离订阅不代表立即结束。官方说明，未被任何客户端打开且闲置 30 分钟的会话会结束；也可能随 CLI 正常关闭而结束。这里只在旧会话的 SessionEnd 到来时评估，不用新会话的 SessionStart 猜测旧会话 ID，也不扫描最近任务。因此不承诺 `/clear` 当场更新旧标题。详见 [官方生命周期说明](https://learn.chatgpt.com/docs/hooks)。

会话退出只增加检查机会，不是 completed 的证据。单独的“可以提交”“可以推送”指令不代表已完成；最终交付已确认且无剩余工作时才可增加 `✓`。正在运行、失败或被中断的最后一轮不生成标题，保留原名。

可以直接让 Agent「暂停自动命名」「固定这个话题的标题」「恢复这个话题的自动命名」「预览这个话题的新标题」。插件内置的 Skill 会调用程序入口。

也可以在插件目录中运行：

```sh
python3 scripts/oil_codex_title.py doctor
python3 scripts/oil_codex_title.py status
python3 scripts/oil_codex_title.py usage
python3 scripts/oil_codex_title.py configure --model gpt-5.6-luna --service-tier fast
python3 scripts/oil_codex_title.py configure --model gpt-5.3-codex-spark --service-tier standard
python3 scripts/oil_codex_title.py rename <话题ID>
python3 scripts/oil_codex_title.py rename <话题ID> --apply
python3 scripts/oil_codex_title.py lock <话题ID>
python3 scripts/oil_codex_title.py unlock <话题ID>
python3 scripts/oil_codex_title.py pause
python3 scripts/oil_codex_title.py resume
```

`rename` 默认只预览。`--apply` 才写入标题，并读回核验标题元数据。它不保证桌面置顶缓存已刷新；桌面显示限制见 [发布验收](发布验收.md)。

Fast 是服务档位，不是另一个模型 ID。Spark 使用标准档位，模型本身以速度为重点。切换模型时若未指定服务档位，程序会清除旧模型的 Fast 设置，避免把不支持的档位传给新模型。

## 数据与并发边界

`usage` 汇总新版启用后的独立模型账本，按命名/归档和模型分组，展示调用尝试、Token、未知用量与处理结果。缓存命中包含在输入 Token 内，推理 Token 包含在输出内；未知不等于零，不换算账号额度。账本先记录启动，再记录模型返回与最终处理状态，校验失败、过期结果、格式复核及重名重试均保留独立记录。超时或进程中断只有已返回的用量可统计，其他标为未知。

账本保存在数据目录的 `usage/日期/`，仅含时间、用途、模型、话题 ID、用量、耗时和状态，不含标题、原文或错误详情。它不统计宿主管理 Agent；旧日志不合并进账本，避免迁移时重复计数。保留日志中的纯确认跳过数另列，日志轮转后可能少于历史总数。

配置、每话题状态和简短日志默认位于 `$CODEX_HOME/oil-codex-title`；未设置 `CODEX_HOME` 时使用用户主目录下的 `.codex/oil-codex-title`。可用 `OIL_CODEX_TITLE_DATA` 指定独立测试目录。未知配置字段会保留。

对话摘录仅传给当前登录所使用的 Codex 模型服务；不向其他服务发送。插件不保存完整对话或命名提示词。临时模型会话使用 `--ephemeral`，输出临时文件用完删除。持久日志只记录状态、候选标题、简短理由与用量，每个话题按容量轮转。

后台 Hook 只返回空 JSON，不返回额外上下文、警告消息或续聊指令，因此命名内容不会追加到正常对话。Codex 仍可能显示 Hook 的执行状态或宿主自身产生的错误。

同一话题使用进程锁；新 Hook 最多等待两个模型超时窗口加 20 秒，释放锁后重新判断最新轮次，避免漏掉快速连续对话的最后一次请求。重复内容跳过模型调用；独立模型禁用 Hook，避免递归。同工作目录中发现与已记录标题重名时最多额外生成一次，仍冲突就返回 ambiguous_title。写入前重新读取话题，如果标题或对话已变化，就丢弃旧结果。官方改名 API 没有原子条件更新，最后一次检查与写入之间仍存在极短的并发窗口。

插件成功完成一次标题评估或写入后，才建立稳定基线；此后检测到外部改名会自动锁定。首次生成过程中，Codex 可能还在设置首轮标题，这类变化会丢弃旧结果，但不会自动锁定。首次处理前无法可靠区分宿主自动标题与用户手动标题，需要保留的标题请主动 `lock`。暂停或锁定不会取消已产生的模型费用。

## 兼容性与限制

- macOS：优先发现桌面 App 自带的 Codex；可用 `configure --codex-bin <路径>` 覆盖。
- Linux：保留 POSIX 内核锁，纳入跨平台自动化测试；桌面体验未实测。
- Windows：已适配原生启动、内核文件锁和 UTF-8；验收范围见 [Windows 安装与验证](Windows安装与验证.md)，不能把程序测试等同于桌面自动触发实测。
- 云端和 ChatGPT Work：不支持此本地话题适配器。
- 离线：可以查看配置和暂停，生成标题需要连接模型服务。
- 某些旧 CLI 无法读取桌面端的新存储格式；兼容性检查失败时保留原标题。
- 插件只响应安装之后实际触发的轮次，不自动扫描或批量修改历史话题。
- Hook 信任和功能开关由 Codex 管理；程序不会绕过或自行写入信任记录。
